## 4. قرارات لازمة حسب وقتها — DECISION

1. **قبل هيكل المشروع:** تثبيت بيئة التطوير والتشغيل (نسخ SDK وAngular وSQL Server ودعم الشبكة الداخلية) واسم أول Issue ونطاقها، ومكان تشغيل الاختبارات وإدارة الأسرار. أسماء المشاريع المختصرة المقترحة حسب توجيه المالك: `api`, `application`, `core`, `infrastructure`, `client`, `tests`. هذا اقتراح تنظيم، ليس إنشاء ملف.
2. **قبل P1/SQL:** تحديد قواعد الشخص ذي علاقتي عمل، نطاق فرادة المرتب الرئيسي على `AccountingUnit/Employment/EntitlementMonth` وما يترتب على النقل، وإقرار علاقات `Person`, `EmploymentRelationship`, `PayeeRelationship` ومقاطع التاريخ والهوية؛ لا تعميم بدون سند.
3. **قبل P2:** تعريف عقد PDF/Excel/DirectForm ومعنى `EvidenceAuthenticity` و`SourceCoverage` والهوية المجهولة وفشل الصف وتكرار الكود، وتجميد `SourceSnapshot`؛ لا مساواة إدخال يدوي بوثيقة Oracle رسمية.
4. **قبل P3/الاعتماد:** صلاحيات رد المركزية، والتكليف، وحسم الملاحظة، وإعادة الفتح واعتماد الصرفية بمعناها ونسختها؛ فصل `Reported` عن `Verified`.
5. **قبل P5:** توثيق أنواع البنود المطلوبة من المالك (مرجع الدرجة التاريخية، ووعاء **أساسي 30/6/2015**، ونسبة + مبلغ مقطوع، ومقطوع فقط) بمعايير قبول ومراجع مالية أصلية، مع تطبيق `FinancialRuleVersion/RuleEffect` دون استخدام الأساسي الحالي بدل التاريخي. **هذه الجزئية طُرحت في الحوار وتحتاج إدراجًا تفصيليًا لاحقًا في سجل القرارات؛ ليست نسبة قانونية مُعتمدة.**

## 5. ما يمكن تأجيله — DEFERRED (دون فقد المتطلب)

- تفاصيل ألوان التبويبات والبطاقات ونهايات تصميم واجهات الموظفين؛ D-043–D-045 ثبتت تجربة الملف على مستوى العمل ولا تستلزم رسم كل زر الآن.
- تفعيل كافة قوانين المرتبات ونسبها قبل تجربة مسار مراجعة يعتمد على قيم أصلية وقرارات مراجعين **دون حساب مستقل وهمي**.
- تفاصيل نسب وقواعد كل صندوق: طلب المالك **عدم الانشغال بها الآن**. يظل D-046 ملزمًا بحفظ مبالغ كل صندوق مستقلًا ومرادفات Oracle الشهرية، ولا يُختلق حساب نسبة لها.
- تفاصيل الشجرة الحكومية الرسمية والربط النهائي بكل بند قبل أن تصل مصادرها المعتمدة؛ لا تمنع تصميم عقد المراجع المالي، لكنها تمنع تفعيل `Mapping` غير موثق في الإنتاج.
- متابعة متقدمة للفروق والمتجمدات ومزايا تقارير لاحقة، بشرط عدم تسمية نسخة محدودة بأنها تنفيذ كامل أو إهمال المكونات الداخلة صراحة في أول MVP.

## 6. ما هو جاهز لإعادة الاستخدام — READY

- **منهج معتمد:** `DDD + Modular Monolith + Clean Architecture + OOP/SOLID`، كما في ADR-003/004/005. اعتماد المبادئ لا يساوي اعتماد الجداول أو تفاصيل Aggregates.
- **حقيقة نطاق العمل:** النظام للمراجعة والتوثيق، لا تنفيذ صرف/خصم أو تعديل Oracle؛ يشمل الطب والأسنان والصيدلة ومستحقي الصرف غير الموظفين.
- **عقود فصل المعاني:** `SourceAmount` و`ExpectedAmount` و`ReviewedAmount` و`OfficialCorrectionAmount` و`VerifiedPaidAmount`، والحفظ التاريخي للنسخ والتصحيحات، والفصل بين شخص وعلاقة عمل وعلاقة صرف.
- **مسار إدخال بديل مثبت بالمتطلبات:** PDF عند توافره، وExcel أو إدخال مباشر، دون افتراض OCR كشرط؛ كل ظهور سطر يحتفظ بكوده واسمه وموقعه.
- **مرجع لمعايير الاختبارات:** مصفوفة `PLAN-01..45` ووثائق سيناريوهات `DDD/TR/HR/DF/OV/DD`؛ **معايير قبول تصميمية وليست اختبارات منفذة**.

## 7. أول مهمتين مقترحتين — دون ترخيص تنفيذ آلي

### `BOOT-001` — إعداد هيكل المشروع (مسموح التخطيط له الآن)

**المدخل:** ADR لاختيار الإصدارات، وIssue ينفّذها Gemini بعد إذن مالك صريح. **النطاق المحدود:** Solution باسم `PayrollReviewSystem` ومشاريع `api/application/core/infrastructure` وAngular `client` واختبارات مناسبة، وفحص بناء فارغ، وCI بدون أسرار، و`README` يشرح تشغيل البيئة.

**معايير قبول قابلة للاختبار:** 
- يبني الـBackend ويشغّل اختبار وحدة بسيط باعتماديات صحيحة؛ وAngular ينجح في build/test أساسي وفق الإصدارات التي اعتمدها المالك.
- لا يُرجع `core` إلى EF أو PDFium أو Angular؛ `infrastructure` يعتمد على عقود داخلية وليس العكس. لا مشروع عام ضخم باسم النظام قبل أسماء الطبقات المختصرة.
- لا SQL migrations، ولا تعريف قوانين أو نسب أو واجهات مصرفية أو موظفين حقيقيين.
- PR برمجي منفصل، اختبارات حقيقية بنتائجها، مراجعة diff وخصوصية؛ **لا دمج كود أو نشر بدون تفويض المالك**.

### `P1-IDENTITY-001` — أول جزء Domain بعد البوابات

**الهدف:** تمثيل `Person` و`EmploymentRelationship` و`PayeeRelationship` تاريخيًا واختبار تطابق العلاقة المستفيدة وعدم افتراض وظيفة لمستحق مكافأة.

**اختبارات أولية لازمة:** شخص له عمل واحد واستحقاقان يظهر مرة واحدة في البحث لكن العلاقات منفصلة؛ مستحق مكافأة بلا عمل؛ شخصان لهما الاسم نفسه؛ علاقتا عمل مشروعـتان في فترتين؛ هوية مصدر غير محسومة لا تدمج شخصين؛ ترقية بأثر تاريخي لا تمحو الدرجة السابقة. **يُمنع التنفيذ حتى إغلاق موانع P1 ومراجعتها المستقلة**.
