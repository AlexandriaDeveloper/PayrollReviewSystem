# دليل تشغيل مراجعة الخطة على Gemini / Antigravity

**الغرض:** تشغيل مراجعة مستقلة للخطة والرسوم، وحفظ دليل ما نفذ. هذا الدليل لا يشهد بأن ملحق Antigravity شُغّل من هذه المحادثة. راجع [حالة التقارير السابقة](../egm/REVIEW-STATUS.md) ولا تخلطها بمراجعة هذه الحزمة.

## 1. ملفات العمل

- ابدأ بـ[البرومبت الرئيسي](GEMINI-ANTIGRAVITY-MASTER-PROMPT-AR.md).
- الهدف: [الخطة الشاملة](COMPREHENSIVE-WORK-PLAN-AR.md)، والرسوم [UML](UML-AR.md) و[ERD](DATABASE-DIAGRAM-AR.md)، و[مصفوفة القبول](REQUIREMENTS-AND-ACCEPTANCE-MATRIX.md).
- السياق المرجعي: AGENTS وGEMINI وقاعدة العمل ومتطلبات المالك وسجل القرارات ومعايير الهندسة، ثم المواصفات المرتبطة. احفظ قائمة القراءة صراحة، ولا تنقل المحادثة السابقة إلى المراجع.
- مجلد النتائج المقترح: `docs/planning/reviews/<run-id>/` داخل نسخة المشروع. يحفظ التشغيل الجديد في مجلد جديد، دون استبدال تقارير نوفمبر السابقة.

هذه قائمة أولية وليست شهادة تغطية كل ما ينتجه المنفذ. يسجل `TargetFiles` جميع الملفات الجديدة أو المعدلة وبصماتها، بما فيها القراءة والأدلة والافتراضات والقرارات والـBacklog. كل مخرج إما يدخل جولة محددة أو يسجل استبعاده وسببه ونطاق الحكم؛ يمكن تقسيم الحزمة إلى جولات دون تعميم حكم إحداها على الأخرى.

## 2. التحقق من البيئة

تحقق من الملحق الكامل والشخصيات والمعايير وأداة إنشاء مراجع بسياق جديد. في Antigravity CLI يورد الدليل الرسمي أمر `agy plugin install https://github.com/google/elephant-goldfish-model`؛ وفي App أو امتداد IDE يبدأ الاكتشاف من `/plugin`. لا تفترض أن النسخة المستقلة تدعم المراجعين؛ افحص القدرة الفعلية. اقرأ النسخة المثبتة من مهارة المراجعة قبل التشغيل، واتبع ترتيب مراحلها. [المصدر الرسمي للبيئات](https://github.com/google/elephant-goldfish-model/blob/main/docs/harnesses.md)، و[المهارة](https://github.com/google/elephant-goldfish-model/blob/main/skills/egm-review/SKILL.md)، تاريخ التحقق 11 نوفمبر 2026.

إذا غابت القدرة، سجل `BLOCKED_ENVIRONMENT` لبوابة المراجعة، وسلم المسودات وما يمكن فحصه. تقمص الشخصيات داخل محادثة واحدة ليس مراجعة مستقلة. لا تدّعِ تركيب الملحق أو تشغيله من مجرد قراءة هذا الدليل.

## 3. طريقة العمل المقترحة

1. Elephant يقرأ المراجع ويثبت النسخة، ثم يعد مسودة كاملة وروابطها وافتراضاتها.
2. يختار تشغيلًا مجمعًا وفق مهارة EGM المثبتة ويعطيها TargetFile وGoldfishContext صريحين. لا تفرض عدد المراحل من قائمة تقارير قديمة.
3. ينشأ كل مراجع بسياق محادثة جديد. يراجع وضوح النص، وحماية الثوابت، وتناسب التصميم، وقابلية تحويله إلى مهام وعقود، وحدود الجاهزية.
4. تحفظ النتائج الأصلية، ثم يصنف Elephant كل ملاحظة: إصلاح، أو رفض مسند، أو سؤال مالك، أو مصدر قانوني مطلوب. لا تعني درجة BLOCKER تلقائيًا صحة نقد يخالف المواصفة.
5. تصحح الأجزاء المثبتة، وتعاد مراجعة الأثر مع النسخة الجديدة. يظل اعتماد التصميم ونطاق الكود قرارًا منفصلًا.

## 4. ما الذي نطلب من المراجع اختباره؟

| المحور | اختبار النقد |
| --- | --- |
| فهم المستخدم | هل يفسر الفرق بين سحب الملاحظة وتنفيذ فرق مؤجل؟ وهل يعرف من يفعل ماذا؟ |
| الهوية والشهر | هل يرفض القيد مكافأتين مشروعتين أو يسمح برئيسيين بسبب اختلاف مجموعة أو مصدر؟ |
| المصدر | هل تبقى الأسطر المتكررة والسالب والتغطية والبديل بلا مرفق صادقة؟ |
| النطاق والنسخة | هل يمكن رد على نسخة قديمة أو اعتماد معاينة قديمة بعد تغيير مؤثر؟ |
| الفروق | هل يمكن تخصيص دليل واحد مرتين أو الخلط بين ظهور مبلغ وتحققه؟ |
| السلطة والقانون | هل تبدو نسبة أو صلاحية أو جواز تسوية كقرار مؤكد بلا سند؟ |
| OOP/SOLID | هل المسؤوليات والاتجاهات تحمي السلوك، أم مجرد واجهات وتسميات؟ |
| الرسوم والبيانات | هل المفاتيح والتعددية والاختيارية متسقة بين النص وUML وERD؟ |
| التشغيل | هل توجد مهمة كاملة ذات قبول واختبار، وخطة تجربة واستعادة وقياس؟ |

## 5. سجل التشغيل المطلوب

| الحقل | ما يسجل |
| --- | --- |
| RunId / AgentId | المعرف الأصلي من البيئة، لا اسم مخترع لإثبات التشغيل |
| Host / Version / Plugin | البيئة والنسخ الفعلية وكيف تحقق الاكتشاف |
| Target / SHA / Hashes | هدف الجولة، ونسخة الأساس، وبصمات ملفات المسودة |
| ReadFiles | ما قرئ فعلًا، وما تعذر أو بقي جزئيًا |
| ContextIsolation | أداة العزل وإعدادها؛ فصل المحادثة مستقل عن استبعاد تعليمات المضيف |
| StartedAt / CompletedAt | أوقات فعلية، والحالة؛ البداية ليست اكتمالًا |
| Findings | ID ودرجة وملف وسطر وسيناريو وأثر واختبار قبول |
| Resolution | استجابة المصمم وسبب قبول أو رفض النقد والقرار المطلوب |
| Recheck | النسخة الجديدة والجزء المعاد فحصه وما بقي مفتوحًا |

أي حقل لا تكشفه البيئة يوصف `NOT_EXPOSED` أو `UNAVAILABLE` مع السبب وأثر النقص وكيف جرى التحقق مما أمكن. لا يستخدم معرف تقديري؛ ويخص `BLOCKED_ENVIRONMENT` تعذر قدرة ضرورية فعلًا، لا نقص بيان ثانوي مع وجود المراجع المستقل.

يجب أن تظهر حدود الفحص كما هي: مراجعة نص أو رسم لا تساوي تجربة برنامج، وعرض Mermaid لا يثبت صحة قاعدة مالية، ولا تُرفع حالة قراءة أصل لمجرد نقله إلى المستودع.
