# ADR-005 — معايير هندسة البرمجيات وAgent Skills الموجهة إلى Gemini

**الحالة: ACCEPTED — اعتماد المالك لمنهج جودة التطوير (7 نوفمبر 2026).**
**المستودع:** `AlexandriaDeveloper/PayrollReviewSystem`.
**Issue:** [#33](https://github.com/AlexandriaDeveloper/PayrollReviewSystem/issues/33).
**قرارات سابقة:** [ADR-003](ADR-003-ddd-modular-monolith-clean-architecture.md) و[ADR-004](ADR-004-object-oriented-and-solid-principles.md).

## الدافع
اعتماد `DDD + Modular Monolith + Clean Architecture + OOP + SOLID` يحدد أسلوب التصميم، لكنه وحده لا يضمن أن نتائج الحسابات المالية صحيحة، ولا أن كل تغيير مجرب وآمن ومقاس. المالك طلب إيصال معايير الجودة العشرة إلى Gemini بصورة قابلة للتفعيل والمراجعة، وليس مجرد قائمة أسماء.

## القرار المعتمد
1. تطبيق [معايير الهندسة العشرة](../engineering/ENGINEERING-STANDARDS.md) و[Definition of Done](../engineering/DEFINITION-OF-DONE.md) على **كل مهام الكود المصرح بها** بحسب أثر المهمة، مع اشتراط أدلة حقيقة بدل إعلان النجاح.
2. حفظ مهارتين محليتين قابلتين للاكتشاف في بيئات Antigravity/Gemini المتوافقة:
   - [`payroll-engineering-quality`](../../.agents/skills/payroll-engineering-quality/SKILL.md): تخطيط/تصميم/تنفيذ مُصرح لقواعد النظام، وتحديد الاختبارات قبل التعديل.
   - [`payroll-pr-quality-gate`](../../.agents/skills/payroll-pr-quality-gate/SKILL.md): مراجعة فروق PR والاختبارات ومعايير القبول وقرار `PASS/FAIL/NOT_RUN/N/A` مستند إلى أدلة.
3. ربط هاتين المهارتين بـ`GEMINI.md`, `AGENTS.md`, `REVIEW-GATES.md`, و`.github/PULL_REQUEST_TEMPLATE.md`. **الاكتشاف أو التنشيط الفعلي على جهاز المالك يحتاج تحديث مستودعه وإعادة تحميل Skills في جلسة مدعومة؛ لا ندعي حدوثه من GitHub وحده.**
4. الالتزام بـTDD للقواعد المالية الجديدة عندما تكون قابلة للاختبار أولًا، وبـRegression test قبل إصلاح خلل قابل لإعادة الإنتاج متى أمكن؛ أي استثناء يجب تسبيبه. لا ندعي دورة Red-Green-Refactor إذا لم تكن مثبتة.
5. **تعريف النجاح بالتناسب مع المخاطر:** Code PR مع اختبارات فشل حتمية / تكامل DB / API / أمان / أداء بحسب التغيير؛ لا نفرض اختبارات أداء لمجرد تعديل نص رسالة، ولا نُسقط حماية البيانات لتوفير الوقت.
6. `Build` أخضر أو `CI` أخضر لا يثبت صحة تقرير Oracle أو سند قانوني. التنوع في عينات الاختبار، نسخ التاريخ، القيود الذرية ومصدر الاعتماد لا يُستعاض عنها بدرجة تغطية رقمية وحدها.

## الحدود وما لم يُفوض به
- هذا القرار **معايير للمستقبل** وليس تصريحًا لـGemini بكتابة كود الآن، ولا لتعديل ملفات CI أو SQL أو قواعد الإنتاج أو نشر البرنامج.
- لا اختيار نهائي لمنتج قاعدة بيانات أو إصدارات `.NET/Angular` أو `DB migrations` بدون القرارات والمهام المناسبة.
- لا جعل `Microservices` أو `CQRS` أو Event Sourcing أو `interface` لكل كلاس متطلبات افتراضية.
- Goldfish الجاري على حزمة الراتب الأساسية **لا يصبح تلقائيًا مراجعةً لهذه المعايير**؛ يظل إقرار الـBounded Contexts والـAggregates والـSchema تحت مراجعة مستقلة.

## أثر القبول
على كل PR برمجي لاحق تقديم Evidence Matrix واضحة، وسبب أي `N/A`، والإبلاغ عن `NOT_RUN`، ومخاطر البيانات المالية، وخطة ترحيل وتراجع عند الحاجة. يجب عرض المشكلات المانعة في الوقت المناسب، وليس إخفاؤها لحفظ الشكل النهائي للتسليم.

**ملاحظة تشغيل:** `SKILL.md` معيار تعليمات لوكيل؛ ليس قدرة سحرية تضمن الاختبار أو الوصول إلى الجهاز، ولا يمنح صلاحيات جديدة.
