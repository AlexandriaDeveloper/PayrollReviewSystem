# الرقابة الاستثنائية: الأجر النقدي أثناء جزء الوقت مقابل وعاء المعاشات

**مثال تشغيل أكده مالك النظام في 6 نوفمبر 2026؛ لم يُتحقق بعد من النص القانوني المنطبق على كل كادر.** لا تفعّل تقريرًا قانونيًا حاسمًا قبل توثيق النص والسريان والقرارات.

## المشكلة
قد يخفض قرار عمل جزءًا من الوقت **استحقاقات الموظف النقدية**، بينما يستمر استخدام **وعاء التأمين/المعاش المعتمد** عن الأجر الكامل في الحالة التي وصفها المالك. أحيانًا تحسب المركزية الاشتراك على المبلغ النقدي المخفض، فيجب أن يكتشف البرنامج ذلك **كاستثناء ضيق**، رغم أن حساب التأمينات العادي خارج نطاق مراجعة الوحدة.

## مثال بأرقام افتراضية
| البيان | قبل القرار | بعد القرار |
| --- | ---: | ---: |
| الأجر النقدي | 1000 | 650 |
| نسبة استحقاق النقد وفق القرار في المثال | 100% | 65% |
| **وعاء الاشتراك التأميني المعتمد لهذا الموظف في المثال** | **1000** | **1000** |
| الوعاء الذي ظهر أن المركزية استخدمته خطأ | — | 650 |

**تحذير:** 1000 هنا **وعاء الاشتراك** وليس «قيمة خصم المعاشات». لا يعني المثال خصم 1000 من المرتب، ولا يجعل نسبة 65% قاعدة عامة لكل الموظفين. وقد يختلف الوعاء المعتمد عن الأجر النقدي الكامل في حالات أخرى.

## الحقول المقترحة للنموذج
| الحقل | المعنى |
| --- | --- |
| \`WorkArrangementType\` | نوع العمل الكامل أو جزء الوقت من قرار معتمد |
| \`WorkArrangementEffectiveFrom/To\` | نطاق تطبيق القرار المالي |
| \`CashEntitlementFraction\` | 0.65 في المثال فقط، لا قيمة افتراضية عامة |
| \`FullTimeReferenceCashEntitlement\` | الأجر النقدي المرجعي للقرار |
| \`ReducedCashEntitlement\` | المبلغ النقدي المقترح أو الذي اعتمده المراجع |
| \`ApprovedInsuredWageBase\` | وعاء الاشتراك المعتمد المستقل للفترة والكادر |
| \`CentralReportedInsuredWageBase\` | الوعاء الذي تؤكده مستندات المركزية إن كان متاحًا |
| \`CentralReportedInsuranceDeduction\` | المبلغ المخصوم في PDF، وليس الوعاء |
| \`RuleAndEvidenceVersion\` | النص والقرار وفترة السريان والدليل |
| \`AuditFlag\` | اختلاف / وعاء مجهول / قاعدة غير مثبتة / لا استثناء / تمت المراجعة |

## خطوات الرقابة المقترحة
1. تحقق من وجود قرار جزء وقت معتمد في فترة الاستحقاق.
2. استخرج **وعاء المعاشات المعتمد** من مصدر مستقل موثق ومناسب للكادر والتاريخ.
3. إذا وفر المصدر الرسمي الوعاء الذي استخدمته المركزية، قارنه بالمعتمد وفق سياسة التقريب المثبتة.
4. إن لم يذكر PDF الوعاء، **لا تستنتجه من قيمة الخصم** دون قانون ومعادلة معتمدين؛ اطلب دليلًا.
5. إذا ثبت الوعاء المعتمد 1000 والمستخدم 650 في الفترة نفسها، سجل \`PensionBaseMismatch\` وطلب اعتراض/تصحيح مع الدليل.
6. يُظهر النظام للمراجع القرار، ويترك ملف Oracle الأصلي والمبلغ المخصوم دون تغيير مباشر.

## حالات الاختبار
| الاختبار | الوضع | النتيجة |
| --- | --- | --- |
| PT-001 | نقد 650، وعاء معتمد 1000، المركزية استخدمت 1000 | لا اعتراض على الوعاء |
| PT-002 | نقد 650، وعاء معتمد 1000، المركزية استخدمت 650 | اعتراض حتى لو الصافي متطابق |
| PT-003 | PDF يذكر خصم 75 ولا يذكر الوعاء | طلب مستند، بلا استنتاج قيمة الوعاء |
| PT-004 | موظف يعمل كامل الوقت | لا تشغيل استثناء جزء الوقت |
| PT-005 | القرار أو الكادر أو النص القانوني غير متحقق | تحذير، لا حكم قانوني آلي |
| PT-006 | قرار يسري من منتصف الشهر | حساب الفترات المتأثرة حسب السريان الحقيقي |
| PT-007 | نسبة 65% غير منطبقة على فئة أخرى | لا تعميم للنسبة |
| PT-008 | الوعاء المعتمد لا يساوي الأجر النقدي الكامل | الاعتماد على الوعاء المثبت، لا إجمالي المرتب السابق |
| PT-009 | وصل مستند مركزي مصحح | احتفظ بالقديم والجديد وأعد مطابقة الملاحظة |

## الحوكمة
هذه **رقابة على وعاء بعينه** وليست طلبًا لمحرك ضريبة/تأمين شامل. يلزم النص الرسمي والقرارات وتواريخ السريان وموافقة الجهة المختصة قبل تنشيط قاعدة حساب قطعية. الاعتراض لا يعدل الخصم المركزي مباشرة.
