# التعاون بين مالك النظام وChatGPT وGemini عبر GitHub

## المرجع الوحيد للعمل
تُستخدم `Issues` للقرارات والمهام، و`Pull Requests` لتغيير الكود ومراجعته، و`ADR` لقرارات التصميم، و`docs/` للاحتفاظ بالمعرفة. المحادثة وحدها ليست تصريحًا خفيًا لتنفيذ كود.

## الأدوار
- المالك: يقرر سياسات العمل والأولوية والقواعد القانونية ونطاق التنفيذ والدمج البرمجي والنشر.
- ChatGPT: يُحلل المتطلبات، ويحدد المهام ومعايير قبولها، ويطالع تغييرات PR والاختبارات، ويعلق على المخاطر والتصحيحات.
- Gemini: ينفذ المهام المحددة، يرفع فرعًا وPR مع الأدلة، ويجيب عن ملاحظات المراجعة.
- GitHub: قناة الاتصال الدائمة التي تحفظ السياق والكود والقرارات.

## دورة التطوير
1. توثيق المتطلب وحدوده.
2. إنشاء Issue تصف الحالة الحالية والمطلوب وأمثلة الإدخال والإخراج والاختبارات.
3. اعتماد المالك **لنطاق تنفيذ الكود**.
4. إنشاء Gemini فرعًا من أحدث `main` وPR مبدئيًا `Draft`.
5. فحص ChatGPT للكود الحقيقي وتصنيف الملاحظات:
   - **BLOCKER / مانع:** خطأ مالي أو قاعدة مختلقة أو فقد إثبات أو هوية غير صحيحة أو تسريب بيانات.
   - **MAJOR / جوهري:** عدم استكمال مطلب أو اختبار أساسي أو مخطط ترحيل.
   - **MINOR / محدود:** تحسين تنسيق أو صيانة لا يفسد السلوك.
   - **QUESTION / استيضاح:** مسألة بحاجة لقرار المالك أو سند أصلي.
6. يرد Gemini على كل ملاحظة بتعديل واختبار، ثم تراجع النسخة الجديدة من رأس الفرع.
7. دمج الكود والنشر من اختصاص المعتمدين من المالك فقط؛ **الدمج لا يعني النشر**.
8. تحديث الوثائق وسجل القرارات عند تغير أي قاعدة.

## تفويض المالك لدمج Markdown (6 نوفمبر 2026)
فوض المالك ChatGPT في **مراجعة ودمج PRs التي تحتوي على تغييرات `.md` فقط دون طلب إذن متكرر**، بشرط:
- قراءة قائمة الملفات الكاملة والاختلافات الفعلية، والتحقق أنها توثيق فقط ولا تتضمن كودًا أو إعدادات تشغيل.
- فحص الأسرار وبيانات الموظفين والرواتب، والتأكد من عدم تحويل ادعاء قانوني أو اقتراح إلى قاعدة معتمدة دون سند.
- معالجة تعارضات التوثيق مع الاحتفاظ بالمحتوى الصحيح والتحقق مرة أخرى قبل الدمج.
- ربط التغيير بالمهمة وتوثيق SHA الدمج، وترك المسائل الجوهرية المجهولة معلقة عند اللزوم.
- لا يجوز تعميم التصريح على `.cs` أو `.ts` أو SQL أو ملفات CI أو أسرار أو هجرات أو نشر أو مستودعات أخرى.
- **Gemini لا يدمج PRs الخاصة به تلقائيًا** حتى لو كانت Documentation؛ دور الدمج المفوض هو ChatGPT بعد المراجعة.
- أي تغيير قانوني أو قرار تجاري غير مثبت يظل مقترحًا لحين اعتماد صاحبه.
- مهمة المتابعة الآلية، إن كانت مفعلة، تخضع للقيود نفسها. **كتابة هذا النص وحدها لا تنشئ مهمة آلية**.

## سياسة لغة التوثيق وأمثلة البيانات
جميع ملفات Markdown الجديدة والتعديلات اللاحقة في هذا المستودع تُكتب **باللغة العربية الواضحة**، بما فيها الأوصاف، وخطوات المراجعة، والجداول، وأسماء الحالات المعروضة للمستخدم. تُبقى أسماء الملفات ومسارات GitHub والمعرفات التقنية (Classes, API, JSON fields, SQL columns, test IDs, SHA) **كما هي بالإنجليزية** حتى لا تنكسر العقود البرمجية أو مراجع GitHub. يجب وضع مثال اصطناعي للمدخلات والمخرجات وأثر الجداول أو الكلاسات في كل تصميم جوهري، مع رابط لمخطط ERD/UML المناسب. لا تُستخدم بيانات موظفين حقيقية، ولا تُستبدل قاعدة غير متحققة بمثال افتراضي.

## نمط التسليم
وصف PR: المهمة والسبب والمرجع والمكونات والتجارب والمصادر والأسئلة والخصوصية والتوافق.
تعليق المراجعة: درجة المشكلة + الملف والسطر + طريقة إعادة إنتاجها + النتيجة الصحيحة + الاختبار المطلوب.
بعد تعديلات Gemini: رابط Issue/PR والفرع وSHA والملفات ونتائج الاختبار والعوائق.

## عدم الادعاء بوجود اتصال آني
الذكاء الاصطناعي لا يقرأ تلقائيًا كل تعليق لحظة كتابته. تتم المراجعة عند استدعاء ChatGPT أو من خلال مهمة متابعة **مفعلة فعلًا**. الإشارة إلى بوت على GitHub لا تضمن التنفيذ الفوري.

## تعريف اكتمال المهمة
تنفيذ النطاق المعتمد؛ حل الموانع؛ اختبارات حتمية ناجحة؛ عدم إدراج مستندات سرية؛ تحديث التصميم والمصادر؛ مراجعة diff الحقيقي؛ وعدم تغيير الإنتاج دون تحكم.

## نقطة البداية
وثائق التصميم وحدها لا تخوّل إنشاء تطبيق أو ترحيل قاعدة البيانات. تُفعّل كل مرحلة برمجية بمهمة محددة ومعتمدة.

## EGM ضمن تعاون ChatGPT وGemini — تفويض إعداد فقط
**قرار المالك الحالي**: ChatGPT يصمم (Elephant)، وتُحفظ حزم التصميم على GitHub، ويُجري مراجع Goldfish مستقل بفصل سياق فعلي مراجعةً قبل تنفيذ القرارات الجوهرية، ثم يقرر المالك اعتماد التصميم ومنح إذن مهمة Gemini. 
- GitHub لا ينشئ مراجع Goldfish بمجرد كتابة Issue؛ يجب استخدام Plugin/Agent بيئة مدعومة وإثبات تشغيله.
- ChatGPT يمكنه إعداد الوثائق ومراجعة تقارير Goldfish وإصلاح توثيق `.md` بحدود التفويض؛ لا يصح أن يكتب ChatGPT تقريرًا بوصفه ناتج Goldfish لنفس تصميمه.
- راجع `docs/egm/README.md` و`docs/egm/REVIEW-PROTOCOL.md`، واحفظ `NOT_RUN` حتى وصول نتيجة مستقلة.
- الإذن بتحديث Markdown لا يشمل تثبيت أدوات على جهاز المالك، أو تغيير GitHub Actions/branch rules، أو تنفيذ كود أو ترحيل أو نشر.
