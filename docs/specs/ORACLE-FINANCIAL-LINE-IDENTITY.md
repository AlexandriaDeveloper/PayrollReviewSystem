# مواصفة هوية السطر المالي وعلاج الأسماء العربية في Oracle

**الحالة: مقترح تصميم قبل تنفيذ كود.** أكد المالك أن كود الحساب الواحد قد يتكرر أكثر من مرة في الاستحقاقات أو الاستقطاعات، وأن أسماء البنود العربية قد تظهر معكوسة أو مشوهة أو متجزئة.

## القاعدة الأساسية
**لا تجعل الكود أو الكود+الاسم مفتاحًا فريدًا للسطر المالي.**

ممنوع اعتبار `Dictionary<AccountCode,amount>` أو `Dictionary<AccountCode+Label,amount>` سجلًا كاملًا للمصدر؛ لأنهما قد يدمجان بدلين أو استقطاعين مختلفين في قيمة واحدة. السطر هو **ظهور مستقل داخل مستند وصف وصفحة وجانب محددين**، ويحتفظ برقم داخلي خاص به حتى لو تشابه مع غيره.

## نموذج `SourceFinancialOccurrence` المقترح

| الحقل | ما يمثله |
| --- | --- |
| `SourceLineId` | معرّف داخلي فريد لهذا الظهور، لا يعتمد على الكود |
| `SourceDocumentId` و`OriginalHash` | رابط PDF الأصلي وإصداره وبصمته |
| `ImportAttemptId` و`ParserVersion` و`AdapterName` | أي محاولة قراءة وأي محرك وإصدار استخدم |
| `ReportType` و`ReportPeriod` و`EmployerUnit` | نوع الصرفية والشهر والجهة المؤسسية |
| `SourceRecipientOccurrenceId` | ظهور المستفيد في هذا التقرير، لا هوية الشخص المعتمدة |
| `PageNumber` و`TableIndex` و`RowIndex` و`PaneIndex` و`CellIds/TextOffsets` | موقع السطر والخلايا أو النص داخل المستند |
| `OccurrenceOrder` | ترتيب الظهور داخل المصدر، وليس بندًا قانونيًا |
| `FinancialSide` | استحقاق أو استقطاع أو حصة جهة معلوماتية أو مجموع أو مجهول |
| `RawCode` | الكود كما ورد حرفيًا وقد يكون مجهولًا |
| `RawLabel` | الاسم الأصلي مهما كان ترتيب الحروف والتباعد |
| `NormalizedLabelCandidates` | احتمالات اسم مقروء دون تغيير الأصل |
| `RawAmountToken` | رقم المبلغ الأصلي بإشارته وفواصله وأرقامه |
| `ParsedAmount` و`SignStatus` | قيمة `decimal` محتملة وحالة إثبات السالب |
| `ClassificationStatus` و`ExtractionIssues` | جودة استخراج هذا السطر ومشكلاته |
| `CanonicalComponentId` و`MappingDecisionId` | ربط **لاحق** ببند معتمد وقرار مراجع |
| `EntitlementPeriod` و`MovementType` | الفترة الأصلية وهل الحركة حالية أو متجمدات، إن ثبت ذلك |

## مثال بأرقام افتراضية

| ظهور السطر | الجانب | كود Oracle | اسم البند | المبلغ | التصرف |
| --- | --- | --- | --- | ---: | --- |
| `L-01` | استحقاق | `21110505` | العلاوة الخاصة 2014 | 15 | سطر مستقل |
| `L-02` | استحقاق | `21110505` | العلاوة الخاصة 2015 | 25 | سطر آخر |
| `L-03` | استحقاق | `21110101` | المرتب الأساسي | 500 | شهر جارٍ |
| `L-04` | استحقاق | `21110101` | المرتب الأساسي أثر رجعي | 35 | حركة مختلفة أصلها غير مؤكد بعد |
| `L-05` | استقطاع | `41110104` | صندوق دعم متحدي الإعاقة | 10 | بند مصدري بعد التحقق من الربط |

جميع المبالغ افتراضية، والأكواد أمثلة شكلية ظهرت في دراسات سابقة وليست اعتمادًا رسميًا عامًا لكل التقارير.

## مراحل قراءة السطر وتفسيره
1. قراءة النص **بترتيبه الأصلي** مع إحداثيات الكلمات والخلايا عند توافرها.
2. إنشاء احتمالات تطبيع عربية على مستوى الخلية: `NFKC`، توحيد أرقام عربية/فارسية، والألف/الهمزة والمسافات وأشكال العرض؛ لا تقلب **كل صفحة** عشوائيًا.
3. فصل كود الحساب ورقم المبلغ وأجزائه واسم البند وعنوان القسم، وربطها بمواقع الصف الفيزيائي ونصف الجدول الصحيح.
4. بناء **مرشحين** للبند الداخلي من الجانب والسياق والكود والاسم البديل المعتمد والفترة والكادر وطبيعة الحركة.
5. إذا بقي أكثر من بند محتمل، تسجل `MappingAmbiguous` ليحسمها المراجع.
6. يستطيع المراجع اعتماد اسم بديل أو تصحيحه **بحدود كادر وفترة ونطاق** مع إصدارات وتاريخ؛ لا يتغير `RawLabel`.
7. مطابقة الإجماليات يمكن أن تحدث قبل حسم الاسم، لكنها لا تعني اكتمال صحة تفاصيل البنود.
8. تصدير Excel قد يعرض **مجموعًا اختياريًا** للبند، لكن يجب الاحتفاظ بكل صف أصلي في شاشة التفاصيل والتصدير الرقابي.
9. تطابق الكود والاسم والمبلغ نفسه في صفين لا يسمح بجمعهما أو حذف أحدهما؛ يجب فحص مكان المصدر لاحتمال تكرار استخراج أو ورود حقيقي مرتين.
10. ظهور عدة بنود متوقعة تحت سطر واحد من Oracle يسجل `LineAllocation` متعددًا لمتعدد، وقد يقره المراجع كاستثناء باب صرف موثق دون مسح الفروق الأصلية.

## أمثلة لمشكلات العربية
- `ةصاخلا ةوالعلا` مقابل «العلاوة الخاصة».
- أرقام `٠١٢٣` و`۰۱۲۳` والأرقام اللاتينية، والفواصل `٫` و`،` و`,` والنقطة.
- اسم بند موزع على سطرين أو ثلاثة.
- مبلغ ملتصق بالكلمة مثل «الأساسي٥٠٠».
- سنة `2014` أو `2015` جزء من اسم العلاوة، **ليست مبلغًا**.
- رقم حساب في نهاية السطر أو مبلغ قبله.
- رمز `x` لملخص لا يجوز احتسابه كقيمة مستحقة.
- سالب قبل الرقم أو بعده أو بين قوسين.
- استحقاقات واستقطاعات في نصفين متقابلين من الصف نفسه.
- ثقة 100% في قراءة الاسم لا يجوز إعلانها لمجرد نجاح الجمع الحسابي.

فصل أسباب الغموض إلى: **اسم، مبلغ، إشارة، جانب مالي، هوية شخص، بند قانوني**؛ لكل منها نتيجة مراجعة مختلفة.

## حالات اختبار اصطناعية
| الاختبار | السلوك المتوقع |
| --- | --- |
| ID-01 | كود واحد لعلاوتين تاريخيتين مختلفتين: يحتفظ باثنين `SourceLineId` |
| ID-02 | كود واسم متطابقان في موقعين: سطران مع تنبيه احتمال الازدواج |
| ID-03 | كود يظهر في سياق استحقاق وسياق استقطاع: جانب كل سطر محفوظ |
| ID-04 | رقم قومي واحد وله علاقات صرف مشروعة متعددة: لا دمج زائف |
| AR-01 | عربي معكوس ومقروء: تُقترح احتمالات اسم واحد بعد إثبات، والأصل محفوظ |
| AR-02 | الاسم مكسور عبر خلايا أو صفحات: يستعاد بدليل أو يتطلب مراجعة |
| AR-03 | سنة 2014/2015 بجانب مبلغ: لا تُلتقط السنة باعتبارها القيمة |
| AR-04 | الرقم قبل الاسم والكود في نهاية السطر: ربط صحيح وفق الصف |
| AR-05 | سطر `x` أو متجمد يجاور بندًا عاديًا: لا خلط أو جمع مزدوج |
| AR-06 | `-100.00` أو `100.00-` أو `(100.00)` أو علامة سالب Unicode: حفظ الإشارة أو طلب مراجعة |
| AR-07 | استحقاق واستقطاع بالكود نفسه في عمودين: سطران بجانبين مختلفين |
| AR-08 | لا يوجد دليل على الأعمدة: حالة مجهولة بدل التخمين |
| AR-09 | أكثر من اسم بديل معتمد محتمل: قرار مراجع مع سجل تدقيق |
| AR-10 | تصدير موظفين مختارين: لا تسريب تحذيرات موظفين غير مختارين |

## التوافق مع قواعد الوحدة الحسابية
- المعاشات والصناديق التي حددها المالك: `CENTRAL_SOURCE_AMOUNT` دون حساب نسبة، مع رقابة جودة الملف.
- استثناء جزء الوقت: مقارنة الوعاء التأميني المعتمد والمستخدم عندما تتوافر مصادرهما والقاعدة الموثقة.
- الترقيات والعلاوات: بنود متوقعة وفق تاريخ وقاعدة؛ السطر المستورد لا يتغير.
- تجميع البنود في باب صرف واحد يتطلب قرار مراجع، لا مطابقة آلية مزيفة.

## منع التحديث المباشر
لا يستطيع Parser تحديث `Person` أو الدرجة أو القاعدة أو `ApprovedFinancialFact` أو قرار المراجع أو استيراد معتمد سابق إلا بعملية مستقلة مصرح بها.
