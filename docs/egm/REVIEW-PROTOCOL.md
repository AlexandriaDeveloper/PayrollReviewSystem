# بروتوكول تشغيل Goldfish الحقيقي وتوثيق نتائج المراجعة

> **تحديث الفهرسة في 11 نوفمبر 2026:** راجع [حالة التقارير الحالية](REVIEW-STATUS.md). توجد تقارير فعلية في المستودع؛ استقلال تشغيلها غير متحقق في دراسة التوثيق. عبارات الحالة أدناه تصف مرحلة إعداد سابقة.

**حالة التشغيل الحالية: NOT_RUN.** هذا المستودع نفسه لا يضم EGM plugin المثبَّت ولا Subagent نشطًا. يجب تثبيت الـPlugin في **بيئة التنفيذ الفعلية** التي تملك الوصول إلى نسخة المشروع، والتحقق من قدرة البيئة على إنشاء سياق مستقل.

## 1. تنفيذ التشغيل يدويًا في بيئة تدعم EGM

اختر بيئة مناسبة وتثبيتًا كاملًا لا مجرد نسخ ملفات `skills/`:
- **Antigravity CLI**: الأمر الرسمي `agy plugin install https://github.com/google/elephant-goldfish-model`، ثم جلسة جديدة.
- **Antigravity App / VS Code Extension**: أمر `/plugin` ثم اطلب تثبيت الرابط الرسمي؛ راجع تعليمات المشروع قبل الاعتماد.
- **Codex CLI**: `codex plugin marketplace add google/elephant-goldfish-model` ثم `codex plugin add egm@egm` وجلسة جديدة.
- **ChatGPT/Codex desktop**: لهما plugin منشور بحسب دليل EGM؛ يتطلب تفعيل المستخدم، وليس مثبتًا تلقائيًا هنا.
- **Antigravity IDE Standalone**: تذكر وثائق EGM أنه **غير مدعوم حاليًا** لمراجعة Goldfish الحقيقية لعدم توفر `invoke_subagent`. يمكن تجهيز الملفات فيه، لكن لا تدّعِ حصول مراجعة مستقلة.

مرجع التحقق: [دليل البيئات الرسمي](https://github.com/google/elephant-goldfish-model/blob/main/docs/harnesses.md) و[مهارة EGM review](https://github.com/google/elephant-goldfish-model/blob/main/skills/egm-review/SKILL.md).

## 2. التحقق من عزل السياق
1. افتح نسخة محلية من المستودع وافحص SHA المستقر للـ`main`.
2. في جلسة جديدة للـAgent، شغّل مهارة `egm-review` **على ملف حزمة واحد**؛ لا تضع ملخص هذه المحادثة أو «موافقة ChatGPT على صحة التصميم» داخل توجيهات الـGoldfish.
3. اطلب من المشغّل إثبات أن **Goldfish مراجع فرعي Fresh Context** وليس نفس المحادثة أو ملخص مراجعة الأب. إذا البيئة لا تتيح ذلك، الحالة `BLOCKED_ENVIRONMENT`.
4. لا توصل ذاكرة حوار أو حساب خاص بأدلة رواتب أو بيانات موظفين. مراجع EGM يقرأ ملفات المستودع والمراجع المذكورة فقط.
5. يمكن ضبط `GoldfishContext` بوثائق المشروع المشار إليها في الحزمة. أي URL خارجي أو ملف خارج مجلد المشروع يُطلب تأكيده حسب تعليمات المهارة، ولا يُرسل تقريرًا ماليًا حقيقيًا.
6. تحقق أن المراجع **قرأ المستندات فعلًا** وسجل نسخها، ولم يكتفِ بخلاصة كتبها الـElephant.

## 3. أمر التنفيذ لأول حزمة
بعد تثبيت EGM وفتح المشروع في بيئة تدعم Subagents:

~~~text
/egm:egm-review docs/egm/01-DOMAIN-AND-PAYROLL-DESIGN-DRAFT.md
~~~

الاسم `/egm:egm-review` هو الشكل الموضح لـAntigravity CLI وClaude Code في EGM. في Codex استخدم مهارة `egm-review` من قائمة المهارات. مهارة المراجعة عادةً تسأل عن نوع التشغيل؛ اختر مراجعة كاملة مناسبة للمستند، واتبع تعليمات النسخة المثبتة. لا تُلزم أدوات مختلفة بصيغة أمر غير مدعومة.

ثم حزمة 2:

~~~text
/egm:egm-review docs/egm/02-TEMPORAL-FINANCIAL-RULES-DESIGN-DRAFT.md
~~~

ثم حزمة 3:

~~~text
/egm:egm-review docs/egm/03-ORACLE-INTAKE-AND-EVIDENCE-DESIGN-DRAFT.md
~~~

لو أظهرت المهارة رابط مستند خارجي أو طلبت ملفات إضافية، زودها بالمراجع النصية المنشورة **غير الحساسة** فقط؛ لا تفترض أن اتصال GitHub وحده يشغّل المراجعة.

## 4. أدلة التشغيل المطلوبة
يجب أن يحتوي تقرير كل حزمة على:
- `ReviewRunId`, `TargetPath`, `TargetSha`, `RepoMainSha`, `EGMVersion`, `AgentHarness`, `FreshContextVerified`.
- أسماء مراحل EGM التي **نُفذت فعلًا**، وملفات المصدر التي تمت قراءتها، وروابط/paths التقارير الناتجة.
- نتيجة كل مشكلة برمز ثابت ودرجة `BLOCKER/MAJOR/MINOR/QUESTION` والدليل والسيناريو والاختبار المقترح.
- هل هناك مشكلة قانونية أو بيانات مرجعية تحتاج قرار المالك، وهل الإصلاح في المستند أم الكود أم متطلب جديد.
- نتيجة ختامية: `FAILED_WITH_FINDINGS` أو `REVIEW_COMPLETE_PENDING_OWNER_DECISIONS` أو `NO_BLOCKERS_REPORTED` (مع عدم مساواة ذلك بموافقة تنفيذ).

**لا تعتمد ادعاء `100% verified` دون أثار مراجعة قابلة للفحص.** نموذج التقرير: [القالب](GOLDFISH-FINDINGS-TEMPLATE.md).

## 5. بوابة وقف التنفيذ
لا تبدأ مهمة برمجية جديدة مرتبطة بالحزمة قبل:
- وجود تقرير Goldfish مستقل **قابل للتحقق**.
- حل `BLOCKER` و`MAJOR` المؤثرين على النطاق أو توثيق قرار مالك واعٍ بالمخاطر عند الحاجة، لا تجاهلهم.
- وجود قواعد قانونية أصلية معتمدة لنطاق الحساب (الذكاء الاصطناعي لا يعتمد القانون).
- ADR معتمد للمخطط الفيزيائي وتاريخ السريان والهوية ومفاتيح الفرادة.
- إذن المالك **الصريح** لتنفيذ Issue برمجية محددة. مراجعة EGM لا تعطي Gemini تفويضًا عامًا.

## 6. خصوصية وأمن التوثيق
المستودع عام أو قابل للمشاركة؛ **ممنوع** إدخال ملفات موظفين أو أرقام قومية أو أرقام حساب أو صور Oracle حقيقية أو أي أسرار في `GoldfishContext` أو تقارير GitHub. كل الأمثلة يجب أن تكون اصطناعية. عند نقص قاعدة رسمية: `LEGAL_SOURCE_REQUIRED` بدل ملء النقص بقاعدة تخمينية.

## 7. بعد التنفيذ
بمجرد وجود كود تنفيذي مرتبط بوثائق معتمدة، يمكن استخدام `egm-drift-report` لإبراز اختلافات الكود عن التصميم. ذلك **ليس** بديلًا عن مراجعة الاختبارات الفعلية أو GitHub PR. لا تنشئ مراجعات دورية أو تراقب عمليات المستخدم آليًا دون إنشاء مهمة رسمية مستقلة بموافقة مناسبة.
