# قاعدة العمل الموحدة لنظام مراجعة المرتبات

**الحالة: مرجع العمل المعتمد للتوثيق والتحليل — 11 نوفمبر 2026.**
طلب المالك ضم التوثيق المتاح إلى GitHub واتخاذه قاعدة العمل. يسجل [ADR-006](decisions/ADR-006-consolidated-working-baseline.md) حدود هذا الاعتماد. هذه الصفحة تجمع ما نبدأ منه، وتدل على الوثائق التفصيلية وتوضح ما لم يحسم. لا تمنح تلقائيًا إذن البرمجة أو تفعيل نسب أو مخطط قاعدة بيانات.

## 1. طريق القراءة والعمل

1. اقرأ [تعليمات المشروع](../AGENTS.md) ثم هذه الصفحة و[سجل القرارات](governance/DECISION-REGISTER.md).
2. لفهم الواقع ودورة العمل، اقرأ [تصور المشروع المستخلص من الدراسة](discovery/project-understanding-ar.md)، ثم [متطلبات المالك](governance/OWNER-OPERATING-REQUIREMENTS.md).
3. راجع [المراجعة التفصيلية للمستودع](reviews/2026-11-11-repository-review-ar.md) و[حالة تقارير EGM](egm/REVIEW-STATUS.md) قبل نقل توصية إلى التصميم.
4. اقرأ [فهرس المعرفة البحثية](research/README.md)، و[حالة القراءة](research/notes/source-study-status-ar.md)، و[كل المصادر والمتبقي](research/notes/source-reading-inventory-ar.md). هذه مذكرات بحث، وأصول أدلتها تحفظ في الأرشيف الخاص.
5. لكل مهمة، حدد المتطلب والمصدر والحالة والنسخة ومعايير القبول، واقرأ مواصفاتها من [فهرس التوثيق](README.md). تفعيل حساب أو تغيير معماري يمر ببواباته الموجودة.

## 2. الهدف والنطاق الثابتان

الوحدة الحسابية المركزية للمجمع الطبي بجامعة الإسكندرية، كود `30200105`، تراجع ملفات الاستحقاقات المركزية للطب وطب الأسنان والصيدلة، لفئات الموظفين وأعضاء التدريس والمتعاقدين ومستفيدي المكافآت ضمن القرارات المسجلة. النظام يستقبل المصدر ويدعم فحصه ومقارنته وتوثيق الملاحظات وردود المركزية وحسمها ومتابعة تنفيذ ما اتفق عليه. لا ينفذ صرفًا أو خصمًا أو تغييرًا في Oracle.

الشخص وعلاقة العمل وعلاقة استلام المال مفاهيم مختلفة. مجموعة المراجع الشهرية تختلف عن مجموعة البنك. المرتب الرئيسي واحد منطقيًا داخل نطاق العلاقة والوحدة وشهر الاستحقاق المعتمد، ويمكن أن تكون له عدة مصادر وتصحيحات ومقاطع زمنية. الصرفيات المنفصلة متعددة؛ وسياسة تعدد علاقات العمل أو النقل بين وحدتين تحتاج حسمًا قبل SQL.

## 3. دورة الملاحظة بين الطرفين

وصف المالك يشمل استلام الملف، ومراجعة الوحدة، وإبلاغ الملاحظات، والتعديل أو التأجيل أو التسوية، أو قبول توضيح يثبت سلامة الملف وخطأ المراجع. تحفظ الملاحظة الأصلية وأدلتها والردود وسبب الحسم ومَن اعتمده. حسم الملاحظة ومتابعة تنفيذ فرق مالي حالتان مستقلتان.

| النتيجة التشغيلية | ما يجب أن يبقى في السجل | متى تنتهي المتابعة؟ |
| --- | --- | --- |
| المركزية صححت الملف | الملاحظة والرد والمستند القديم والجديد ومقارنة الأثر وقرار إعادة الفحص | بعد فحص التصحيح وقبول النسخة المرتبطة بالقرار |
| اتفق الطرفان أن الملف سليم | دليل الرد وسبب سحب/تصحيح ملاحظة المراجع وهوية المعتمد | بحسم موثق، دون تحويل الملاحظة المرفوضة إلى فرق مرحل |
| فرق صحيح اتفق على تأجيله | أصل الاستحقاق والبند والفترة والمبلغ وسبب التأجيل والشهر المستهدف والمسؤول | بعد مطابقة ما نفذ والمتبقي بدليل مناسب، مع متابعة الجزء غير المنفذ |
| تسوية كلية أو جزئية | سند جوازها والمصدر الذي نسب التنفيذ للفرق والمبلغ والتاريخ وقرار التحقق | بالقدر المثبت فقط؛ التشابه في المبلغ لا يثبت التسوية |
| خلاف أو مستند ناقص | نطاق الخلاف والطرف المسؤول والمطلوب والأدلة المتعارضة | بعد رد مقبول أو قرار الجهة المختصة، دون افتراض قيمة مجهولة |

**مثال اصطناعي:** المصدر 1200 والمتوقع المستقل المسند 1000. رد يثبت استحقاق 1200 قد ينتهي إلى سحب الملاحظة، بعد مراجعة سنده. رد يقر فرق 200 ويؤجله ينشئ متابعة لذلك الفرق بفترته؛ إذا ثبت تنفيذ 100 منه، تبقى 100. لا يغيّر أي مسار أصل الملف، ولا يعتبر مجرد الوعد أو الظهور في كشف إثبات دفع.

تفاصيل الجولات والإرسال والتصعيد والمواعيد وأدوار إدخال رد المركزية وصلاحيات الاعتماد تحتاج مواصفة تشغيل واعتمادًا. لم يُحسم هل المركزية تعمل بحساب داخل النظام أم تُسجل ردودها لدى الوحدة. لا يفرض هذا الوصف Entity أو API أو Schema بعينه.

## 4. فصل القيم والأدلة

احفظ `SourceAmount` و`ExpectedAmount` و`ReviewedAmount` و`OfficialCorrectionAmount` و`ReportedDisbursementAmount` و`VerifiedPaidAmount` والمتبقي في معانيها المنفصلة. كل اعتماد يتعلق بنطاق ونسخة مصدر وحساب وقرارات محددة. التغيير اللاحق يفتح مراجعة للجزء المتأثر ويحفظ السابق.

كل ظهور أصلي للبند مستقل حتى لو تكرر الكود والاسم. لا يصبح كود Oracle تعريفًا داخليًا وحيدًا للبند. تطابق الصافي لا يلغي اختلاف مكونات الاستحقاق والاستقطاع. المجهول ليس صفرًا؛ وحصة الجهة أو الوعاء المرجعي ليسا نقدًا جديدًا للمستفيد.

## 5. ما نحسبه وما نأخذه من المركزية

- البنود المسموح بحسابها مستقلًا تحتاج وقائع ودرجات مؤرخة ونصًا معتمدًا ووعاءً وتاريخ مرجع وتقريبًا وآثارًا قابلة للتفسير.
- التأمينات والمعاشات المعتادة وصندوقا دعم المعاقين والشهداء تتبع `CENTRAL_SOURCE_AMOUNT` بعد فحص المصدر وفق D-012 وD-015. لا تُنشأ قيمة Expected مستقلة مزيفة لها.
- جزء الوقت له فحص استثنائي لوعاء المعاش عند اكتمال النص وبيانات الوعاء المعتمد والمستخدم؛ قيمة الخصم وحدها لا تثبت الوعاء.
- نسب الإجازة 156% و91% و48/60/200% أمثلة تصميم غير مفعلة. يلزم تثبيت الأوعية والفئة والسريان والأيام والتقريب.
- تتبع فروق الاستحقاقات والاستقطاعات وأدلة تنفيذها مطلوب لدورة العمل. لا يساوي ذلك إنشاء مقاصة بنكية أو ترخيص تسوية بين بندين بلا سند.

## 6. المصادر البديلة والتاريخ

PDF قناة عند توافره؛ البديل الأحدث Excel لموظف وبنوده أو شاشة مباشرة دون ملف، وفق D-020. لا يشترط OCR. البديل يعلن مصدره وتغطيته ودقة نقله ولا يدعي أنه مستند Oracle رسمي.

افصل وقوع الحدث وإصدار القرار والسريان الإداري والأثر المالي وتاريخ العلم وشهر التنفيذ وفترة التسوية. لا تطبق الدرجة الحالية على إجازة قديمة تلقائيًا، ولا تمحُ اعتمادًا تاريخيًا عند وصول مستند متأخر. القاعدة المعتمدة تحدد التاريخ المرجعي لكل بند.

## 7. منزلة كل نوع من الوثائق

| النوع | الاستخدام | حد الاعتماد |
| --- | --- | --- |
| طلب المالك وسجل القرارات | نطاق العمل وتفويض المهام | لا يحل محل السند القانوني اللازم للحساب |
| ADR معتمدة | النهج والقرارات المحددة في نطاقها | اعتماد المنهج لا يعتمد كل تفاصيل الجداول |
| المواصفات | متطلبات وعقود مقترحة أو معتمدة بحسب حالتها | يجب قراءة حالة كل وثيقة |
| مذكرات البحث المنقولة | فهم الأصول والصفحات والتعارضات وأثرها التصميمي | قد تكون تاريخية أو جزئية؛ ليست تشريعًا أو فتوى تشغيل |
| تقارير المراجعة | ملاحظات تُقابل بالمواصفات والدليل | لا تنسخ توصياتها تلقائيًا؛ استقلال EGM لم يُتحقق منه في الدراسة الحالية |
| الأمثلة والاختبارات التصميمية | شرح السلوك وتهيئة الاختبار | ليست نتائج اختبارات منفذة أو نسبًا قانونية |

اعتماد هذه القاعدة لا يحول مقترحات الدراسة إلى قرارات نهائية. تبقى DDD/Modular Monolith/Clean Architecture/OOP/SOLID منهجية معتمدة؛ التقنية وإصداراتها والمخطط الفيزيائي وحدود العقود ما زالت بقراراتها المنفصلة.

## 8. أولويات العمل التالية — مقترح ترتيب

1. تحكيم تعارضات تقارير المراجعة وتثبيت حالة كل ملاحظة بدليلها.
2. إكمال مواصفة دورة ملاحظة ورد وحسم ومتابعة، ثم اختبارها على الأمثلة الخمسة أعلاه.
3. تحديد نطاق الصرفية والمستفيد والإصدار والاعتماد وحالات الرئيسي والتصحيح والمقاطع.
4. استكمال عقد المصدر وقالب Excel والصلاحيات وحفظ الأصل، مع الاستفادة المدروسة من OraclePdfParser.
5. إضافة قواعد حساب قليلة مكتملة السند بدل انتظار اكتمال كل المكتبة، مع إعلان حدود ما فُحص.

هذا ترتيب مقترح للتحليل؛ بدء كود أو SQL أو CI أو نشر يحتاج مهمة محددة وتصريحها وبواباتها.

## 9. تحديث قاعدة العمل

أي معلومة جديدة تسجل بمصدر وتاريخ وحالة: متطلب مؤكد، أو اقتراح، أو نتيجة فحص، أو سؤال مفتوح. يربط التغيير بالوثيقة المعنية وIssue/PR، وتحفظ النسخ السابقة. لا يُرفع أصل خاص أو بيانات موظفين أو مسارات جهاز إلى المستودع. لا يرفع اكتمال نقل المذكرات حالة قراءة مصدر لم يُستكمل.
